## 2. Run the whole system

### Prerequisites

- Node.js 20 or newer (tested on 24).
- Unreal Engine 5.4 with a C++ toolchain: Visual Studio 2022 with *Game development with C++* on Windows, or Xcode/clang on Mac/Linux.
- A C++ UE project. A Blueprint-only project works too: adding a C++ class once converts it.

### Step 1: start the PrimordiaOS bridge

```bash
cd realm-bridge/node-bridge
npm install
npm test
npm start
```

You should see the modules load, then `listening on ws://127.0.0.1:7777 realm=… (realm-5eed1e55)`. Useful flags (each also readable from `PRIMORDIA_<NAME>`):

| Flag | Default | |
|---|---|---|
| `--port` | 7777 | |
| `--host` | 127.0.0.1 | Use `0.0.0.0` only on a trusted network: PRS-1 has no auth. |
| `--hz` | 60 | master loop, clamped to 30–60 |
| `--seed` | 0x5eed1e55 | genesis seed |
| `--evolve` | 15 | seconds between manifest revisions (0 = only on command) |
| `--modules` | – | directory of real PrimordiaOS module implementations (§9) |
| `--validate` | off | schema-check every outgoing packet (debug) |

Optional sanity check from a second terminal, before Unreal is involved:

```bash
npm run watch
```

Expect roughly `heart_beat=60/s cosmic_web=30/s fate_weave=30/s soul_unification=30/s dream_nebula=30/s shadow_inversion=30/s invalid=0`.

### Step 2: install the plugin

1. Copy `unreal/PrimordiaOSRealmBridge/` into `<YourProject>/Plugins/`.
2. Right-click `<YourProject>.uproject` → *Generate Visual Studio project files*.
3. Build the *Development Editor* target in your IDE, or simply open the project and accept the rebuild prompt.
4. In the editor: *Edit → Plugins*, confirm that **PrimordiaOS Realm Bridge** and **Niagara** are enabled.

### Step 3: first light (no art required)

1. Open any level. An empty level with a *Sky Atmosphere*, *Directional Light* and *Exponential Height Fog* works well.
2. Press **Play**. With `bAutoConnect` on (the default), the bridge connects to `ws://127.0.0.1:7777`, receives the manifest, spawns `ARealmRootActor`, and streams entities into it. The bridge terminal prints `UnrealEngine says hello`.
3. In the console (`~`), `Primordia.Stats` should show packets flowing, about 6 live entities, and a latency of a few ms on localhost.

At this stage most things render with engine basic shapes: the heart sphere, node spheres with cylinder edges, ground terraces, stone circles, spires and stars. Glyphs are the exception: the plugin ships `M_PrimordiaSigilVolume`, so sigils, wards, gates and the soul appear as volumetric light from the first run, each inscribed with its manifest `intent`. FateWeave threads draw as built-in glowing tubes (`M_PrimordiaThreadGlow`, also shipped) until you assign `NS_PrimordiaFateWeave`. The nebula cube stays hidden until it has a translucent material.

### Step 4: build the art

Follow [`docs/MATERIALS_AND_NIAGARA.md`](docs/MATERIALS_AND_NIAGARA.md) and assign the assets in *Project Settings → Plugins → PrimordiaOS Realm Bridge → Assets*. Recommended order:

1. `MPC_PrimordiaMetaphysics`
2. `M_PrimordiaHeart`
3. `NS_PrimordiaFateWeave`
4. `M_PrimordiaDreamNebula`
5. the shadow pair
6. the cosmic node and edge materials
7. the layer materials

The glyph material ships with the plugin (see [§6 of the materials guide](docs/MATERIALS_AND_NIAGARA.md#6-volumetric-sigils-m_primordiasigilvolume)); nothing to build.

For the shadow inversion post-process, also set *Project Settings → Rendering → Custom Depth-Stencil Pass = Enabled with Stencil*.

For a reference of the night look (Lumen, volumetric fog, manual exposure, glowing rings over the spires), open `/PrimordiaOSRealmBridge/Maps/NeoGothicCathedral`. See [§9 of the materials guide](docs/MATERIALS_AND_NIAGARA.md#9-neo-gothic-cathedral-look-dev-scene-neogothiccathedral).

### Step 5: drive it

With the game running, try these console commands:

```
Primordia.Perturb entropy 0.95     the heart races, the web rewires faster, more threads, deeper shadow
Primordia.Perturb lucidity 1       the nebula sharpens, the glyph gains complexity, reveries spawn
Primordia.Evolve                   new manifest revision: layers re-densify, sigils born/dissolved
Primordia.Reseed 42                an entirely new realm (new realm_id → full regeneration)
Primordia.Disconnect / Primordia.Connect ws://127.0.0.1:7777
```

Blueprints can do the same (see §7).

### Step 6 (optional): live preview in the editor viewport

Set *Run In Editor World = true* in the plugin settings and reopen the level. Then use *Tools → PrimordiaOS → Connect Editor World*. Live entities are spawned transient, so they never get saved into the level.

### The processing layer: your machine as a realm

```bash
cd realm-bridge/node-bridge
npm start -- --modules realms/machine
```

Run it from `node-bridge`: elsewhere npm can pick up a parent folder's `package.json` and start the wrong server. This replaces all nine reference modules with ones that read the computer the bridge runs on. The result is **"<Host> Crucible"**, a realm that lives at the pace of your hardware. Everything below is live telemetry: per-core CPU load, RAM, the process tree, and network bytes.

| What you see | What it is |
|---|---|
| Heart | The processor's pulse: 48 bpm idle, 180 at full load, cool cyan turning white-hot amber |
| FateWeave threads | One thread per logical core, spinning as fast as that core works and fraying when it's pinned. Two thin outer threads carry network traffic in and out. |
| Cosmic web | The live process tree around a kernel nexus. Mass is memory and glow is CPU; the hungrier a process, the closer it's pulled to the centre. |
| Soul | The machine itself, crowned with the name of whatever program has dominated the CPU for the last few seconds. The top six processes orbit it. Unity is how evenly the cores share the work. |
| Core sigils | `ZERO CORE RUNS THE THREADS`…, one per core, each with its own monogram. Each grows, heats and gains symmetry with its core's load. |
| Memory ward, bus gate | `GUARD THE MEMORY OF <HOST>` and `OPEN THE BUS OF <HOST>` |
| Layers | Wafer ground (a terrace per cache level), a transistor lattice that fills with RAM, a spire per core as tall as the clock, the bus ring, the idle-loop void, and a sky of stars |
| Nebulae and shadow | RAM as a standing nebula. Network bursts arrive as transient clouds (cyan in, magenta out). Memory pressure deepens the shadow and inverts the realm's light. |
| Time | Realm time runs from 0.7× idle to 2× under load |

Run `node examples/machine-check.js` against a running bridge to see what it's reading. The modules live in `node-bridge/realms/machine/`. Process sampling uses `Win32_Process` on Windows and `ps` elsewhere. Network traffic is Windows-only (`netstat -e`) for now.

### Offline realms

*Tools → PrimordiaOS → Spawn Demo Realm*, or *Import PRS-1 Manifest…* (pick `examples/genesis-5eed1e55.prs1.json`), generates a realm with no server running. The topology web is synthesized locally with the same algorithm and seed as the bridge (PRS-1 §4.4). A realm root saved in a level rebuilds itself on BeginPlay from its stored manifest, and has a **Regenerate** button in its Details panel.

## 3. Plugin architecture

### Modules

| Module | Type / phase | Responsibility |
|---|---|---|
| `PrimordiaOSRealmBridge` | Runtime / Default | the whole bridge: networking, parsing, factory, actors, generator, Blueprint API, console commands |
| `PrimordiaOSRealmBridgeEditor` | Editor / PostEngineInit | the *Tools → PrimordiaOS* menu: connect the editor world, import a manifest, spawn the demo realm, open settings |

Runtime dependencies are `Core`, `CoreUObject`, `Engine`, `DeveloperSettings`, `Json`, `JsonUtilities` and `Niagara` (public), plus `WebSockets`, `NiagaraCore`, `RenderCore` and, in editor builds only, `UnrealEd` (private).

### Runtime update loop (`UPrimordiaBridgeSubsystem::Tick`, every frame)

1. **Socket events.** `FPrimordiaWebSocketClient::Tick` drains connect, close and error events that the socket callbacks queued (MPSC queues, so it is safe whatever thread the WebSockets backend calls back on). It also handles reconnects with exponential backoff, 1 s → 15 s.
2. **Drain.** It pops up to `MaxMessagesPerFrame` text frames, including any packets injected from Blueprint.
3. **Parse.** `FPrimordiaPacket::Parse` checks the envelope and keeps the payload as a JSON DOM (no reflection cost).
4. **Coalesce.** Of several upserts for the same `<type>/<id>` in one frame, only the newest is applied. `cosmic_web` edge lists are carried forward. Retires and manifests are never coalesced.
5. **Dispatch.**
   - `realm_manifest` → `SpawnOrUpdateRealm`, which creates the realm root or diffs it (§6).
   - Visual streams → `UPrimordiaActorFactory::Apply`, which spawns on first sight, attaches to the realm root and routes the packet. `op: "retire"` fades the entity out.
   - `ack` failures are logged.
6. **Garbage collection.** While connected, visual entities silent for `EntityTimeoutSeconds` are retired. When disconnected, the realm freezes.

### The actor factory

- **Type → class** resolution order: runtime `RegisterVisualizerClass` → *Project Settings → Actor Class Overrides* → the native default.
- **Registry:** `"<type>/<id>"` → actor. **Adoption** lets the realm generator hand over actors it created, such as the `soul` glyph or the topology web. The live stream then drives that one object instead of spawning a duplicate (PRS-1 §3.6).
- Native visualizers (subclasses of `APrimordiaVisualActor`) get a direct JSON-DOM call. Any other actor implementing `PrimordiaVisualizer` gets the Blueprint event with a `UPrimordiaPayload`.

## 4. Node.js bridge

- `server.js` runs a drift-corrected master timer at 30–60 Hz. **Every module steps every tick**, and each module **samples** at its own stream rate. One JSON encode is shared by all clients.
- On connect it sends `hello`, then the current manifest, then a keyframe of every stream.
- **Per-client controls:** `hello`, `subscribe`, `set_rate`, `request_manifest` and `ping`, plus the commands `evolve_realm`, `reseed`, `perturb` and `load_manifest` (PRS-1 §2.3).
- **Backpressure:** continuous frames are dropped for a client with more than 1 MiB buffered. Manifests, acks and retires are always delivered.
- Packet schemas are in `src/schemas.js` and documented in PRS-1 §2.6. Run with `--validate` to check every packet as it leaves.

Tests (`npm test`) cover:

- deterministic genesis
- 200 evolution steps staying schema-valid
- every topology kind
- a live socket session checking all seven stream types, envelope validity, 60 Hz heart rate, the edge keyframe and manifest evolution
- command acks and `set_rate` throttling

## 5. Visualization actors

All derive from `APrimordiaVisualActor`. That base provides an ordering guard on `seq`, smoothing at frame rate, a retire fade (`RetireAlpha` 1 → 0, then destroy), and an optional `OnPrimordiaPayload` Blueprint event. Each actor's header documents its material and Niagara parameters.

| Actor | Stream | Components | Notes |
|---|---|---|---|
| `AHeartActor` | heart_beat | sphere + point light | dead-reckoned lub-dub pulse, phase-corrected toward the server; emissive and light swell on the beat |
| `ACosmicWebActor` | cosmic_web | instanced nodes + instanced edge segments (2 draw calls total) | per-instance resonance/mass/kind; edges rebuilt only when `rev` changes and bowed toward the centroid |
| `AFateWeaveActor` | fate_weave | Niagara ribbons | Catmull-Rom resampling into stable slots; bound/frayed/severed states; fades threads in and out |
| `ASoulGlyphActor` | soul_unification (+ manifest glyphs) | raymarched volume in a cube (or a billboarded plane) + instanced fragments | accumulated spin; intent inscribed as a letter-wheel monogram; fragments matched by id and emerging from the centre |
| `ADreamNebulaActor` | dream_nebula | raymarch shell + optional Niagara volumetric motes | slow easing; accumulated drift; transient reveries spawned and retired by the server |
| `AShadowInversionActor` | shadow_inversion | reverse-culled hull + stencil core + post-process | one post-process owner per world, so overlaps never invert twice |
| `ARealmRootActor` | realm_manifest | realm container | layers, glyphs and topology; eases metaphysics; time dilation on every child |

## 6. Procedural realm generator

`UPrimordiaRealmGenerator` exposes these functions (all `BlueprintCallable`):

| Function | Does |
|---|---|
| `GenerateRealmFromManifest(Root, Manifest)` | Full generation for a new `realm_id`; otherwise a **diff**: layers by structural hash, glyphs by id, topology only when its spec changes, metaphysics eased over `transition_seconds`. |
| `SpawnLayer(Root, Layer, Seed)` | Builds a layer root at its altitude, with a base mesh (ground/ocean disc, void sphere). It then adds up to three deterministic instanced tiers: fixed, hero and detail, such as terraces, stone circles and rubble, or spire clusters and skirts (PRS-1 §4.3). Density shows a stable prefix of each tier. Art slots per kind and tier are listed in [MATERIALS_AND_NIAGARA.md §7](docs/MATERIALS_AND_NIAGARA.md#7-layer-materials-and-art-m_primordialayer). |
| `SpawnGlyph(Root, Glyph)` | Spawns or updates an `ASoulGlyphActor`. Glyphs with `bound_to` are adopted by the live stream. |
| `SpawnTopology(Root, Topology, Seed)` | Spawns or reuses the realm's `ACosmicWebActor` and seeds it from C++ topology synthesis, unless a live `cosmic_web` stream is already driving it. |
| `ApplyMetaphysics(Root, Metaphysics)` | Writes `MPC_PrimordiaMetaphysics` and the layer material parameters, and sets `CustomTimeDilation` on every realm entity. |
| `ClearRealm(Root)` | Removes all generated content. |

`ARealmRootActor` calls the generator from `ApplyManifest` and runs the metaphysics easing in its own `Tick`. Determinism comes from `FPrimordiaRandom`, which is bit-identical to the bridge's `prng.js` (PRS-1 §4.1).

## 7. Blueprint integration

Every node lives under the **PrimordiaOS** category.

**Connecting**

| Node | |
|---|---|
| **Connect To PrimordiaOS (Async)** | latent; *On Connected* / *On Failed* (timeout) pins |

| Send Primordia Command · Perturb Metaphysics · Request Realm Evolution · Reseed Realm | |
| Get Primordia Stats | |

**Spawning realms**

| Node | |
|---|---|
| Parse Realm Manifest | JSON → `FPrimordiaRealmManifest` (editable struct) |
| Spawn Realm From Manifest / …From Manifest Json / …From File | works without a server |
| Get Active Realm | |
| On the realm actor: Apply Manifest, Regenerate, Destroy Realm; events *On Realm Generated* and *On Metaphysics Settled* | |
| Generator functions (Get Primordia Bridge → Get Generator) | Spawn Layer, Spawn Glyph, Spawn Topology, Apply Metaphysics |

**Updating visualization actors**

| Node | |
|---|---|
| Apply Packet Json | full envelope through the real pipeline (spawn/update/retire); useful for replays and tests |
| Apply Payload To Actor | drive one actor directly, for example from Sequencer or a UI slider |
| Find Primordia Entity / Get All Primordia Entities | |
| Register Visualizer Class | swap in a Blueprint visualizer at runtime |
| `UPrimordiaPayload`: Get Number / Int / String / Bool / Vector / Color / Array Length / Child | path syntax `glyph.symmetry`, `threads[2].color`; vectors converted from meters to cm |

**A custom Blueprint visualizer** comes in two forms:

- **Subclass a native actor**, for example `BP_MyHeart` from `HeartActor`. Tick *Expose Payload To Blueprint* and implement *On Primordia Payload*.
- **Use any actor:** add the *Primordia Visualizer* interface and implement *Receive Primordia Packet* and *Retire Primordia Entity* (the latter must destroy the actor).

Either way, map the class in *Project Settings → Actor Class Overrides* or call *Register Visualizer Class*.

InputAction Chaos (pressed) ─► Perturb Metaphysics [Key: entropy, Value: 0.95]

## 9. Plugging in the real PrimordiaOS modules

The bridge ships with **reference simulations** of all nine modules, so the pipeline runs end to end today. To use the real ones:

1. Create a folder with any of `heart.js`, `soul.js`, `cosmicWeb.js`, `fateWeave.js`, `dreamforge.js`, `shadowforge.js`, `worldforge.js`, `continuum.js` and `omniscience.js`. Each exports:

   ```js
   export function create(seed, options) {
     return {
       name: 'Heart', stream: 'heart_beat', hz: 60,
       init(ctx) {},                       // ctx = { t, state, manifest, realmId }
       step(dt, ctx) {},                   // advance; read/write ctx.state (the metaphysical bus)
       sample(ctx, { full }) { return [{ type: 'heart_beat', id: 'heart', payload: { ... } }]; },
     };
   }
   ```

   Return `op: 'retire'` packets to destroy entities.
2. Run `npm start -- --modules ./path/to/folder`. Files you provide replace the matching reference module; the rest keep running.
3. Run with `--validate` while developing: invalid payloads are logged with JSON paths.

An adapter for an existing class (for example `src/omniscience`'s `captureSnapshot()`) is typically about 20 lines: call it in `step()` and map its output onto `ctx.state` and the payload schema.

## 10. Troubleshooting

| Symptom | Fix |
|---|---|
| `PrimordiaOS link lost (...); retrying` | Bridge not running, or wrong port. Check `npm start` output and `ServerUrl`. |
| Connected, but nothing spawns | `Primordia.Stats`: are packets received? Set `bLogPackets=True`. Is `bAutoSpawnRealmFromManifest` on? |
| Fate threads invisible | `FateRibbonSystem` is unset, or its emitter is not in *Local Space*. |
| Nebula invisible | `NebulaMaterial` is unset (the opaque fallback is hidden on purpose), or `Density` is near 0. |
| Inversion post-process does nothing | Enable *Custom Depth-Stencil Pass = Enabled with Stencil*; check `StencilValue` matches the settings. |
| Entities vanish after 5 s | No upserts arriving for them. Check `subscribe` filters and `SubscribedStreams`. |
| Bridge must be reachable from another PC | `--host 0.0.0.0` on a trusted LAN only; put an authenticating TLS proxy in front for anything else. |
